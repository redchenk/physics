# 格物智能探究平台：本地纵向样板架构

## 1. 目标

平台不是根据一道题给学生贴标签，而是保存并解释一条可回放的探究证据链：

```text
Observe 观察采集
  原始操作事件、实验记录、预测与结论
        ↓
Diagnose 诊断思维
  证据投影、反证、候选判断、证据不足时拒判
        ↓
Intervene 教学干预
  受教师策略和提示预算约束的最小再探究任务
        ↓
Verify 再实验验证
  更换参数或情境，默认无提示完成
        ↓
Teacher OS
  班级分布、单生证据链、教师复核与教学建议
```

当前本地版本已用欧姆定律、凸透镜成像和频率—音调三个任务实现完整纵向样板。声学还提供独立的真实麦克风与可控声音发生器、实时示波、频谱和同标尺 A/B 录制对比；探究引擎只持久化结构化物理读数，不保存原始声音或录音片段。后续学科实验应复用同一流程，不再创建互相隔离的单页状态。

### Sound Physics Module

[`app/sound-physics.ts`](../app/sound-physics.ts) 保存与界面无关的声音测量算法：频率到音名、RMS 到 dBFS、基于自相关首个强峰的基频估计，以及示波器上升过零触发。实时采集和录制回看调用同一组函数，避免两套波形逻辑产生不同标尺；纯函数通过合成 220/440/880 Hz 信号做自动回归测试。

## 2. 深模块与接口

### Classroom Compatibility Module

平台顶层分为“课堂实验、学生探究、教师工作台”，默认进入课堂实验。原有课堂自由演示与新的学习证据流程并行存在，不能用三个智能探究样板替代完整声、光、电实验室。

- `app/classroom-catalog.ts` 统一声明原课堂模块、本地文件路径与哈希导航；浏览器前进、后退可恢复对应板块。
- `scripts/sync-classroom.mjs` 在开发启动和构建时，将现有 HTML 打包到 `public/classroom/`，插入 CSS 和适配脚本，并将 `electricity/` 中的自由电路模块同步到内嵌与旧地址的资源目录。
- `app/classroom-workspace.tsx` 延迟加载用过的实验室，同页切换时保留 iframe 实例、课堂参数和内存记录。
- `public/classroom/classroom.css` 只做排版适配：移除嵌入页重复标题、提高常用字号、响应式装置布局，独立窗口仍保留原页面结构。
- `public/classroom/classroom-bridge.js` 使用同源且来源窗口匹配的消息同步内容高度与激活状态，离开声学时停止声音和采集，并防止迟到授权在隐藏页开启麦克风。
- 自由课堂页不向 `LocalSessionRepository` 写入证据。需要学习证据时使用学生探究及其声音采集工具，继续遵循显式采集与结构化快照边界。

### Free Circuit Module

电学课堂默认进入自由搭建，原有固定演示通过独立页签继续使用。`electricity/circuit-physics.js` 不依赖 DOM，通过导线/闭合开关合并节点，按导电连通分量选参考点，再用电导矩阵求解各节点电势。电源通过含 0.1 Ω 内阻的诺顿等效进入方程，电流表内阻为 0.01 Ω；理想电压表只读取节点电势差，不形成导电边。不同浮空连通分量间的电压返回 `null`，不会人为选择共同地线制造读数。滑动变阻器为 A–W、W–B 两段电阻，零阻值端点合并节点。

`electricity/circuit-builder.js` 管理元件坐标、接线、撤销/重做、示例、仪表量程与带接线快照的记录。移动或旋转只改变画面，电气连接由接线柱 ID 决定，交叉导线不隐式连接。所有接法调用同一求解器；短路、浮空、超量程和反接由计算结果产生提示。编辑器状态不写入学生探究档案，刷新时清除，课堂数据可导出 CSV。

源代码为本地经典脚本，离线 HTML 可直接运行，无外部资源和新依赖。`tests/circuit-physics.test.mjs` 覆盖实际改接、串并联、桥式网络、多电源、三端变阻器、错误接线及三个入口的资源一致性。

### Inquiry Engine Module

[`app/inquiry-engine.ts`](../app/inquiry-engine.ts) 是平台的核心深模块。UI 只调用状态转换接口，不在 JSX 中散落诊断规则：

- `createSession`
- `submitPrediction`
- `submitPlan`
- `changeParameter` / `captureMeasurement`
- `captureSoundObservation`（示波器实时或片段的派生读数）
- `finishCollection`
- `submitConclusion`
- `acceptLatestIntervention`
- `beginVerification` / `submitVerification`
- `retryAfterFailedVerification`
- `applyTeacherOverride`
- `summarizeSessions`

[`app/inquiry-insights.ts`](../app/inquiry-insights.ts) 从同一会话生成六维过程画像、七个构念的班级证据地图和按事件索引重建的历史装置状态。Teacher OS 使用 [`app/teacher-evidence.tsx`](../app/teacher-evidence.tsx) 展示逐步/自动回放及证据定位，不另存一套可写的学生状态。

其 Implementation 内部负责阶段不变量、物理计算、证据抽取、可拒判诊断、干预选择、提示预算和迁移验证。这个小 Interface 隐藏了大部分策略复杂度，便于测试和后续替换。

### Repository Seam

[`app/inquiry-repository.ts`](../app/inquiry-repository.ts) 定义 `SessionRepository` Interface，并提供两个 Adapter：

- `LocalSessionRepository`：本地验证时写入浏览器 `localStorage`，含版本和损坏回退。
- `MemorySessionRepository`：纯内存隔离副本，用于自动测试。

这条 Seam 是未来部署时的替换点。接入后端时可增加 `D1SessionRepository` 或 API Adapter，无需修改 Inquiry Engine。

## 3. 唯一事实源

同一 `InquirySession` 同时服务学生端与 Teacher OS。教师工作台不维护第二套成绩或结论，只读取：

```text
InquiryEvent[]
  ├─ Measurement[]
  ├─ Evidence[]
  ├─ Diagnosis[]
  ├─ Intervention[]
  ├─ VerificationResult
  └─ TeacherOverride[]
```

教师复核是追加事件。有效视图可以排除被教师否决的候选判断，但原机器判断和复核历史仍留在事件时间线中。

`conclusionEvidenceIds` 明确关联学生亲自选择的记录。新采集事件包含当时全部结构化读数，移除记录后仍可在历史时间点回放；旧事件无快照且原记录已不存在时，返回“不完整”而不生成替代数据。`Intervention.closedAt` 防止过期未接受提示在新结论后重新激活。误概念升级证据同时引用学生观点和构成探针的两条采集事件。

## 4. 诊断边界

- 记录不足时返回 `insufficient`，不能把缺数据解释为学生错误。
- 单一观点证据可返回 `possible`，显示为候选并要求新情境确认。
- 支持证据和反证必须同时保留。
- 可信度对学生仅显示“较低 / 中等 / 较高”，不制造虚假的精确百分比。
- “本次未观察到困难”不等于“已经掌握”。只有无提示新情境验证通过，才报告本次独立迁移成功。
- Teacher OS 不做学生排名，不产生永久能力标签。

## 5. 本地状态机

```text
prediction
  → plan
  → experiment ⇄ experiment（调参、记录、移除记录）
  → conclusion
  → diagnosis
      ├─ 接受最小任务 → experiment（必须新增记录）
      └─ 进入验证 → verification
  → complete
      └─ 未通过时返回实验补证 → conclusion → diagnosis → verification
```

引擎拒绝以下非法转换：跳过预测提交计划、非实验阶段记录、记录少于三组、三个自变量取值不充分、接受干预后没有新增记录、未进入验证便提交答案等。

实验阶段允许修订变量计划。采集完成检查依据学生当前计划选择的自变量，诊断依据任务的规范变量模型，因而既允许错误方案成为可讨论的过程证据，又能让学生在反馈后改进方案。补证必须形成可区分的、仍存在的对照，新结论必须引用本轮新增的有效记录。

Repository 会校验事件类型、事件所属会话/学科/任务版本、选项与变量白名单及基本阶段语义。损坏数据不会被空白工作区静默覆盖；UI 提供原始备份和二次确认清除。旧版缺失的结论引用、干预关闭时间和教师诊断版本会进行兼容迁移。

## 6. 新实验模块接入约定

下一步将物理模型和任务定义提取为 `ExperimentModule` Interface。每个学科 Implementation 应就近包含：

1. 初始参数与参数约束。
2. 无副作用的物理计算函数。
3. 可记录的数据字段与单位。
4. 预测和结论题目。
5. 证据门槛、支持条件与反证条件。
6. 最小干预任务。
7. 至少一个改变参数或表征的无提示迁移任务。

后续接入顺序：光的反射/折射 → 串并联与伏安特性 → 电磁感应 → 力学运动与能量。仪器实时绘制属于各实验 Implementation；事件、证据、策略与 Teacher OS 保持共享，从而获得跨模块 Leverage 和高 Locality。

## 7. 部署前的后端替换点

本轮仅做本地验证，不部署。正式课堂多设备版至少需要：

- 教师身份与课堂 PIN。
- 服务端会话序号与幂等事件写入。
- 班级任务、学生匿名标识和最小权限。
- 数据保留期限、导出与删除机制。
- 声学当前 A/B 原始波形仅暂存在页面内存，刷新即清除；正式课堂版默认只持久化频率、振幅、频谱等派生特征，不保存原始音频。
- 实时课堂投影的同步 Adapter。

这些能力应加在 Repository / Sync Adapter 边界，不进入物理模型或诊断规则。

## 8. 本地验证门槛

统一命令 `npm run verify` 必须通过：

- TypeScript 类型检查。
- Inquiry Engine、Repository 与声音测量算法自动测试。
- 事件回放、过程画像、认知地图的分母与教师复核优先级测试。
- 当前应用代码检查。
- Vinext 本地生产构建。

浏览器人工复核时重点检查：结论提交前无规律泄露、参数键盘可操作、F/2F 标注、补证据闭环、演示数据来源标记、教师否决后汇总变化、刷新后恢复本机会话，以及麦克风权限拒绝后的恢复说明。

当前实现使用本地确定性诊断规则，识别 `P01–P02` 两类探究策略与 `M01–M05` 五类候选误概念；没有接入通用语言模型，不能把保存自由文本称作已完成开放式语义理解。班级地图按当前来源/任务筛选，未评估不计作掌握，教师否决不计作通过。
